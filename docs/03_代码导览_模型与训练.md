## model.py — 多任务网络

### 结构 (MultiTaskNet)
- 输入 [B,32] → 共享骨干 Linear(32→128)+ReLU+Linear(128→128)+ReLU → 两个头:
  - `cls_head`: Linear(128→5) → logits (5 类原始分数)
  - `reg_head`: Linear(128→5 或 6) → 归一化目标 (raw 5 维 / sincos 6 维)
- 【原理】共享骨干 = hard parameter sharing; 两个头是线性的, 非线性特征全部由骨干学。
- 【易错点】回归头输出的是**归一化目标**不是物理量 (直接乘范围才是物理参数, 见 denormalize)。
- 【怎么验证】手算参数量:
  - 骨干: 32×128+128 = 4224, 128×128+128 = 16512
  - 两个头: (5×128+5) ×2 = 1290 (raw) → 合计 **22026**; sincos 回归头 6 维: +129 → **22155**
  - 与训练时打印的"模型参数量"核对; 运行 `python model.py` 看自检输出。

### NPU 部署兼容性 (文件顶部注释清单)
- 只 Linear+ReLU / batch=1 / 通道数为 4 的倍数 / softmax 不进图 / 双头多输出待验证
- 【原理】部署约束是**结构性**的, 必须开发早期内建, 后期改结构代价极大。

## train.py — 训练与评估

### 1) 数据准备 (build_data)
- 固定种子一次性生成 train/val; 监督目标 = `normalize_params(raw, phase_repr)`
- 【原理】固定数据集 → 实验之间严格可比。
- 【易错点】忘记把 phase_repr 传进去 → 目标布局 (5 列) 与模型输出 (6 维) 对不上。
- 【怎么验证】打印 `d["params_norm"].shape`: raw 模式 [n,5], sincos 模式 [n,6]。

### 2) 多任务损失 (multi_task_loss + _loss_weights)
- $L = \lambda_c \cdot CE + \lambda_r \cdot \text{masked\&weighted MSE}$
- 权重展开: 5 个物理权重 → 目标空间 (sincos 时 φ 的权重复制到 cos/sin 两列)
- masked MSE 分母 = `(mask*w).sum()` —— **不是元素总数**!
- 【易错点】分母写错 (用元素总数) 会把损失稀释几倍, 梯度变小, "训练看起来正常但学得慢", 很难察觉。
- 【怎么验证】把 reg_weights 临时设为 (1,0,0,0,0) 跑一步: reg loss 应只包含 A 的误差。

### 3) 评估 (evaluate) 的四个口径
- acc / 各参数 MAE (物理单位, 只统计 mask 内) / φ 圆周误差 / recon
- φ 圆周误差: 差值 wrap 到 [−π, π] 再取绝对值 —— 否则 0/2π 翻转让指标虚高
- recon: 用**真实类别**的公式重建 → 先隔离评估回归本身 (分类错误的端到端影响留给后续 evaluate.py)
- 【易错点】recon 若顺手用了"预测类别", 口径就和实验档案不一致, 数值没法对比。
- 【怎么验证】跑一次 3 epoch 小训练, 看指标量级: recon 应低于 0.6 并下降。

### 4) 训练循环 (main)
- for epoch: 打乱索引 → 按 batch 取数 → forward → loss → zero_grad → backward → step
- 每个 epoch 末尾: `scheduler.step()` (余弦: 1e-3 → 1e-4) → evaluate → 记录 log → 按 val_total 保存 best.pt
- 【原理】best.pt 按"验证总损失"选 —— 多任务里"最优"是加权综合, 本身就是一个可讨论的研究点。
- 【易错点】漏掉 scheduler.step() 会让"余弦衰减"名存实亡; evaluate 忘记 model.eval() 同理。
- 【怎么验证】打开 runs/<name>/log.json, 看 lr 是否在 60 个 epoch 内从 1e-3 降到 1e-4。
